# OSCMidi — une interface de régie

OSCMidi est un outil Windows de connexion MIDI, RTP-MIDI, OSC et VST, développé en React/Tauri. L'utilisateur souhaite une interface qui semble moins générée et standard. La direction retenue est celle d'un panneau de régie : le trajet du signal et les informations techniques donnent son identité au produit.

## Audit et direction

Évaluation initiale : **Needs work**. L'app possède déjà une navigation claire et des composants familiers, mais son identité visuelle exprime peu son rôle de régie MIDI/OSC.

- **High, jugement de design :** halos, grain, cartes translucides et mouvements de survol se cumulent sans expliquer les connexions. Retirer ces accessoires et conserver des surfaces opaques.
- **High :** la commande principale est répétée dans la sidebar et le dashboard, et cachée en bas de navigation. La placer dans la barre supérieure, accessible depuis toutes les pages. `buttons.md › Style` : “Keep the number of prominent buttons to one or two per view.”
- **Medium :** quatre cartes de même importance masquent le parcours du signal. Donner la première place aux connexions configurées et séparer leur configuration de l'activité réelle. `layout.md › Visual hierarchy` : “Order content by relative importance.”
- **Medium :** les boutons de fenêtre imitent macOS alors que le produit est Windows uniquement. Utiliser les symboles et l'ordre Windows. C'est une adaptation au système cible, pas une application des conventions macOS.
- **Contrôle d'accessibilité :** texte secondaire et variantes de badges doivent atteindre 4,5:1 sur leurs surfaces. Ce contrôle seul ne constitue pas un défaut mesuré de l'ancienne interface. `dark-mode.md › Dark Mode colors` : “At a minimum, make sure the contrast ratio between colors is no lower than 4.5:1.”

Références lues : `C:/Users/robin/.codex/skills/apple-design/references/`, notamment accessibility, layout, typography, color, designing-for-macos, sidebars, buttons, lists-and-tables, text-fields, dark-mode et cross-platform.

## Système visuel

Six rôles principaux, clair / sombre : fond #F3F4F4 / #171C20 ; panneau #FFFFFF / #20272C ; texte #20282D / #E5EBEE ; secondaire #58656C / #A6B3BC ; accent #285C75 / #8CC0D8 ; signal positif #287052 / #8BD5B1. Les alertes possèdent leurs propres rôles sémantiques. Vérifier les contrastes calculés avant livraison.

Segoe UI et polices système pour titres et contrôles ; Consolas / monospace pour ports, adresses et chiffres. Échelle : titre de page 24 px, titre de section 16 px, corps 14 px, métadonnées 12 px. Pas de police distante ni de nouvelle dépendance. Grille de 4/8 px, angles modérés, bordures explicites, pas de flou sur le contenu. Aucune animation décorative.

Régulier :
```
Navigation | Page                     Démarrer | outils | − □ ×
           | Titre / description
           | Sources → état du bridge → Destinations
           | Moteur audio             | Réseau OSC / RTP
           | Événements récents
```
Compact :
```
Icônes | Page + commande + outils + fenêtre
       | Titre / description
       | Sources
       | État du bridge
       | Destinations
       | Audio / Réseau / Événements empilés
```

La signature est le trajet du signal, un élément fonctionnel propre au produit. Un traitement type console très sombre et des faux vumètres ont été écartés : ils imposeraient une ambiance et inventeraient de l'activité. La représentation utilise uniquement la configuration et les états déjà fournis par le backend.

## Contraintes et validation

Conserver le backend, les préférences existantes, les trois palettes, les traductions FR/EN, la navigation et le raccourci Ctrl+K. Les connexions configurées ne prouvent pas une activité réelle. RTP et audio ont des cycles de vie indépendants du bridge. L'état affiché doit respecter cette distinction.

Vérifier focus clavier, contraste, réduction des mouvements, couleurs forcées, largeur minimale native 1240 px et zoom 200 %. Vérifier aussi une largeur de navigateur compacte. Les composants de formulaire existants restent en place. Tester les nouveaux liens et états du trajet du signal, puis lint, tests frontend et build. Les captures navigateur utilisent un backend simulé ; elles ne valident pas le MIDI ou l'audio natifs.

- `npm run lint` : ESLint et TypeScript passent.
- `npm test -- --exclude 'artifacts/**' --exclude 'vendor/**'` : 28 fichiers, 119 tests passent. Les exclusions évitent les copies historiques du dépôt dans les artefacts locaux ignorés.
- `npm run build` : passe. Avertissement Browserslist sur les données de navigateurs anciennes ; aucune dépendance mise à niveau dans cette intervention.
- `git diff --check` : passe. Revue indépendante : aucun défaut important restant après correction des prédicats de configuration RTP.
- 11 paires de couleurs contrôlées dans chacune des trois palettes. Texte secondaire / panneau : clair **6,01:1**, sombre **7,06:1**, contraste **12,32:1**. Les 33 paires contrôlées dépassent **4,5:1**. Ce contrôle des rôles sémantiques n'est pas un audit exhaustif de tous les textes et états de formulaire existants.
- Dashboard : aucun débordement horizontal mesuré à 1240, 620 et 320 px, ni avec une taille de texte doublée à 1240 px. Le container query empile le trajet du signal selon l'espace réellement disponible.
- Navigation entre les pages principales, FR/EN, trois palettes, démarrer/arrêter, Ctrl+K, lien d'évitement et focus vérifiés dans Chromium avec données simulées. Couleurs forcées Windows et mouvement réduit inspectés.
- Captures locales : `output/playwright/`. Les essais ne couvrent pas les commandes de fenêtre dans une instance native Tauri ni le matériel audio/MIDI.

Les trois palettes manuelles existantes ont été conservées pour respecter les préférences de cette app Windows. Les composants Radix, Lucide, le comportement de navigation et les traductions restent les fondations de l'interface. Les halos, le grain, les cartes translucides et l'avatar sans fonction ont été retirés.
